All year, this blog repeated the same warning: `sort()`, `reverse()` and `splice()` **change the array in place** — copy it first. In June 2023, the language itself agreed: **ES2023** added non-mutating versions of these methods, plus `findLast` and a couple of smaller features. It's a small release, but it's exactly the piece that was missing for the [immutable style](/blog/2023/04/12/javascript-functional-programming-pure-functions-immutability) we've been using. Let's see each feature with before/after examples, where it helps in React, what browsers support it today — and finish with a recap of this year of JavaScript posts.

## The core idea: the language catches up with immutability

```js
const scores = [30, 10, 20];

// Before ES2023: copy, then mutate the copy
const sorted = [...scores].sort((a, b) => a - b);

// ES2023: one method, no mutation
const sorted2 = scores.toSorted((a, b) => a - b);   // [10, 20, 30]
scores;                                              // [30, 10, 20] — untouched
```

ES2023 is officially "ECMAScript 2023", the yearly version of the JavaScript standard, finalized in June 2023. Its four features:

| Feature | What it adds |
|---|---|
| Change array by copy | `toSorted`, `toReversed`, `toSpliced`, `with` |
| Find from last | `findLast`, `findLastIndex` |
| Hashbang grammar | `#!/usr/bin/env node` officially allowed at the top of a file |
| Symbols as WeakMap keys | Non-registered symbols can be keys of `WeakMap`/`WeakSet` |

> **Rule of thumb: the `to...` methods are the "returns a new array" twins of the old mutating methods.**

## Change array by copy

### toSorted — the twin of sort

```js
const orders = [
  { id: 1, total: 120, date: '2023-11-02' },
  { id: 2, total: 80,  date: '2023-12-01' },
  { id: 3, total: 200, date: '2023-10-15' },
];

// ❌ sort() reorders "orders" itself — and returns the same array
const byTotal = orders.sort((a, b) => a.total - b.total);
byTotal === orders;   // true 😬

// ✅ toSorted() returns a new array
const byTotal2 = orders.toSorted((a, b) => a.total - b.total);
byTotal2 === orders;  // false — orders keeps its order
```

Same comparator as `sort`. Without a comparator, it sorts as **strings**, exactly like `sort` (`[10, 9, 1].toSorted()` → `[1, 10, 9]`) — always pass a comparator for numbers.

### toReversed — the twin of reverse

```js
const latestFirst = orders.toReversed();     // new array, reversed
```

### toSpliced — the twin of splice

`splice` is the most confusing mutating method: it changes the array **and** returns the **removed** items. `toSpliced` returns the **new array**, which is almost always what you wanted:

```js
const steps = ['cart', 'address', 'payment', 'confirm'];

// Remove 1 item at index 1
steps.toSpliced(1, 1);                    // ['cart', 'payment', 'confirm']

// Insert at index 2 (delete 0)
steps.toSpliced(2, 0, 'shipping');        // ['cart', 'address', 'shipping', 'payment', 'confirm']

// Replace 1 item at index 2
steps.toSpliced(2, 1, 'card payment');    // ['cart', 'address', 'card payment', 'confirm']

steps;                                    // unchanged
```

### with — replace one item

```js
const statuses = ['new', 'paid', 'shipped'];

// Before
const updated = statuses.map((s, i) => (i === 1 ? 'refunded' : s));

// ES2023
const updated2 = statuses.with(1, 'refunded');   // ['new', 'refunded', 'shipped']
statuses.with(-1, 'delivered');                  // negative index: from the end
statuses.with(10, 'x');                          // ❌ RangeError: index out of range
```

Unlike `arr[i] = x`, `with` never silently creates holes: an invalid index throws.

### The full mapping

| Mutates the array | Returns a new array (ES2023) |
|---|---|
| `arr.sort(fn)` | `arr.toSorted(fn)` |
| `arr.reverse()` | `arr.toReversed()` |
| `arr.splice(start, count, ...items)` | `arr.toSpliced(start, count, ...items)` |
| `arr[i] = value` | `arr.with(i, value)` |

(`push`, `pop`, `shift`, `unshift` have no twins: spread and `slice` already did the job — `[...arr, x]`, `arr.slice(0, -1)`.)

## Why it matters in React

React needs a **new** array to notice a change (see [reference vs value](/blog/2023/10/11/javascript-reference-vs-value)). The ES2023 methods make the correct code the **shortest** code:

```jsx
function OrderList({ orders }) {
  const [sortKey, setSortKey] = useState('date');

  // ❌ A classic bug: sorting the props array in place during render
  // const visible = orders.sort(byKey(sortKey));

  // ✅ A new array, props untouched
  const visible = orders.toSorted(byKey(sortKey));

  return visible.map((o) => <OrderRow key={o.id} order={o} />);
}
```

```jsx
// Updating state immutably
setLines((lines) => lines.with(index, { ...lines[index], qty: newQty }));   // replace one line
setLines((lines) => lines.toSpliced(index, 1));                           // remove one line
setSteps((steps) => steps.toSpliced(2, 0, 'shipping'));                   // insert
```

The old in-place `sort` on props was a real bug: the parent's array was reordered behind its back, and since it was the **same** reference, `memo` and effects didn't even notice. With `toSorted`, that whole class of bug disappears.

## findLast and findLastIndex

`find` searches from the start. To get the **last** match, we used to reverse a copy:

```js
const events = [
  { type: 'created', at: '10:00' },
  { type: 'status',  at: '10:05', value: 'paid' },
  { type: 'note',    at: '10:07' },
  { type: 'status',  at: '10:30', value: 'shipped' },
];

// Before
const lastStatus = [...events].reverse().find((e) => e.type === 'status');

// ES2023
const lastStatus2 = events.findLast((e) => e.type === 'status');        // { ..., value: 'shipped' }
const lastIndex = events.findLastIndex((e) => e.type === 'status');     // 3
```

No copy, no reversal, and it stops at the first match **from the end** — useful for histories, logs and timelines, where the latest entry is usually the one you want.

## The two small ones

### Hashbang grammar

Node scripts often start with a "shebang" line, so they can be run directly on Linux/macOS:

```js
#!/usr/bin/env node
console.log('Hello from a CLI script');
```

Node always accepted it, but it wasn't part of the language — other tools had to strip it first. ES2023 makes it official: a `#!` line at the very top of a script or module is allowed.

### Symbols as WeakMap keys

`WeakMap` keys used to be objects only. Now non-registered symbols are allowed too (`Symbol('x')`, not `Symbol.for('x')`). It's mostly useful for library authors attaching private data without creating objects as keys. If you've never used `WeakMap`, you can safely ignore this one.

## Can I use it today? (December 2023)

| Feature | Chrome / Edge | Firefox | Safari | Node.js |
|---|---|---|---|---|
| `toSorted`, `toReversed`, `toSpliced`, `with` | 110+ | 115+ | 16+ | 20+ |
| `findLast`, `findLastIndex` | 97+ | 104+ | 15.4+ | 18+ |

Every current browser supports them. Two practical notes:

- **TypeScript** knows these methods from version 5.0 with `"lib": ["ES2023"]` (or `"ESNext"`) in `tsconfig.json` — otherwise you get "Property 'toSorted' does not exist".
- **Older targets** (old company browsers, Node 18 for `toSorted`): use a polyfill like `core-js`, or keep `[...arr].sort()` there. Both are correct — the new methods are just shorter.

## Key rules to remember

| Rule | Why |
|---|---|
| `toSorted`, `toReversed`, `toSpliced`, `with` never mutate | Safe on props, state and shared data |
| `sort` / `reverse` / `splice` still mutate | Use them only on arrays you own |
| Always pass a comparator to `toSorted` for numbers | Default sorting is by string |
| `toSpliced` returns the new array, not the removed items | Unlike `splice` |
| `with(i, v)` throws on an invalid index | No silent holes |
| `findLast` for "the latest matching entry" | No copy, no reverse |
| TypeScript needs `lib: ES2023` | Otherwise the methods don't exist for the compiler |
| Polyfill or keep the copy pattern for old targets | Both are correct |
